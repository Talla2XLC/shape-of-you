# TASK-0145 — подтверждённая прибавка рабочего веса

## Цель

Coach предлагает один точный новый рабочий вес, а после одного ясного
подтверждения API повторно проверяет evidence, Recovery и активную программу и
атомарно сохраняет новую active версию. Без согласия вес не меняется.

## Утверждённое решение

- [ADR](../../../../docs/adr/20260929-confirm-working-weight-increase-atomically.md).
- Предложение является read-only projection для одной точной A/B позиции и
  одного назначения. Источник выполненных sets — только current
  `WorkoutSession`; строгий predicate TASK-0135 не ослабляется.
- Сервер, а не Coach, проверяет безопасность непосредственно перед записью.
- Одна подтверждённая команда создаёт новую immutable версию, активирует её
  и пишет типизированный audit в одной транзакции под Person lock.

## Шаги

1. Зафиксировать критерии TASK-0145 и developer handoff в `4dt-board`.
2. Добавить контракт предложения и подтверждённой команды, типизированную
   audit entity и миграцию с проверкой длины PostgreSQL identifiers.
3. Реализовать свежую серверную Recovery/Training проверку, сравнение revision
   внутри Person-locked transaction, повторный расчёт кандидата и атомарную
   активацию единственного изменённого назначения.
4. Открыть read/write через MCP с явным правилом natural confirmation и
   обязательным read-back после записи; не вызывать write при сомнении.
5. Проверить pure, API, PostgreSQL и MCP сценарии, затем провести независимый
   Quality Review и Architecture Review. После accepted quality обновить
   затронутые current-state Wiki страницы и перенести план в `completed/`.

## Критерии приёмки

- Предложение называет точное упражнение, вес до/после и две подходящие
  сессии. Не предлагает шаг вне правила TASK-0135.
- Без ясного подтверждения программа не меняется. Одно подтверждение
  применяет только предложенное назначение, без дополнительной церемонии.
- Команда повторно проверяет текущую локальную дату, Recovery, две current
  сессии, активную версию/lock и точные параметры. При расхождении нет записи.
- Новая immutable версия становится current и active атомарно; остальные
  поля совпадают с прежней версией. Audit и идемпотентный повтор проверены.
- Garmin не превращается в sets; `body_weight`/`assisted`, неясные данные,
  неблагоприятное восстановление и боль блокируют прибавку.
- Есть unit/integration/MCP тесты, lint/typecheck/build, docs validation,
  независимый Quality Review и Architecture Review.
