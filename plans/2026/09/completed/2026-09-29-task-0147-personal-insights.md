# TASK-0147 — персональные выводы по накопленным данным

Статус: выполнен 2026-09-29; изменения оставлены в основном дереве без коммита.
Архитектура: [ADR](../../../../docs/adr/20260929-compute-evidence-gated-personal-insights-on-read.md).

## Результат

Web Progress и Coach по запросу показывают один и тот же ограниченный набор
объяснимых персональных наблюдений. При недостаточных данных карточка не
появляется. Выводы не дают медицинских оценок и не приписывают причинность.

## Объём

1. Три закрытых вида из ADR: направление веса, изменение числа подтверждённых
   тренировочных дней, наблюдаемая связь тренировки и сна следующего дня.
2. Общий read-only API contract с policy version, окном, выборкой,
   неопределённостью, ограничениями и проверяемыми источниками.
3. HTTP для Web Progress и MCP для Coach используют один расчёт. Расчёт не
   меняет `DailyDecisionContext` или сохранённые решения.
4. Current-only Person evidence; exact Training links; Recovery quality,
   consent и erasure. Полные тексты заметок и raw provider payload не выдавать.

## Последовательность

1. Через 4DreamTeam зафиксировать критерии и план реализации в timeline.
   Проверить пригодность данных обезличенными агрегатами; доступ к staging
   только для чтения. Текущие три записи сна исключают третью карточку.
2. Реализовать чистые policy-функции и ограниченные owner reads. Проверить
   стоимость запросов и отсутствие ненужной новой persistence.
3. Опубликовать contracts, HTTP и MCP; добавить Web карточки на Progress и
   точное объяснение в Coach.
4. Покрыть границы выборки, качество, пропуски, корректировки, приватность,
   источники, одинаковость поверхностей, неизвестность и формулировки тестами.
5. Пройти независимый Quality и Architecture Review. После принятия обновить
   только затронутые текущие Wiki-страницы и проверить docs validator.

## Критерии приёмки

- Каждый вид проходит собственный минимум и скрывается при исключении;
  недоступность одного вида не скрывает пригодные другие.
- Данные и ссылки Person, исправления, consent и erasure не нарушаются.
- Нет двойного счёта связанной тренировки и утверждения, что отсутствие записи
  означает отдых или пропуск.
- Web и Coach используют одинаковую версию и результат API; никакого
  расчёта в LLM и браузере.
- Тесты и независимая проверка принимают каждый критерий; документация
  отражает только реализованное поведение.

## Вне объёма

- Новые медицинские выводы, причинные заявления, прогнозы, автоматические
  изменения плана, push-уведомления и сохранённая история показанных выводов.
- Коммит, push, миграция и деплой без отдельных разрешений.

## Проверка завершения

API: 339 unit и 3 PostgreSQL integration теста, typecheck, lint и build прошли.
Web: 30 unit и 29 browser E2E тестов, typecheck, lint и build прошли.
MCP проверен авторизованным вызовом общего результата. Независимый Quality
принял повторную реализацию после исправления часового порога синхронизации.
`node scripts/validate-docs.mjs` и `git diff --check` прошли. Architecture
Review не обнаружил нового владельца данных, deployable или дублирующего
хранилища; остаётся риск неполной истории у провайдера, поэтому сравнение
сформулировано только по записанным дням и скрывается при недостоверном
состоянии подключения.
