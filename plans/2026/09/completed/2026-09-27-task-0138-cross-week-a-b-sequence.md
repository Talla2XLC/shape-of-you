# TASK-0138 — продолжить A/B через границу недели

## Цель

После A/B/A 21, 23 и 25 сентября выбрать B на 28 сентября при сбросе только
недельной квоты. Сохранить последовательность и после пропущенной недели.

## Утверждённое решение

- [ADR](../../../../docs/adr/20260927-continue-training-sequence-across-weeks.md):
  отделить события текущей недели для квоты от последнего достоверного
  классифицированного якоря той же программы для A/B.
- Использовать действующую проверку совместимости версий; не выводить A/B из
  названия Garmin или неклассифицированной occurrence.
- Staging-классификацию 21 сентября не менять. Самочувствие — отдельное
  решение и не входит в это исправление.

## Шаги

1. Зафиксировать аналитический handoff и developer plan в TASK-0138.
2. Прочитать ограниченную историю current подробных сессий и explicit external
   classifications до начала недели, не расширяя недельный счёт.
3. Продолжить sequence по последнему совместимому якорю; сохранить fail-closed
   поведение для несовместимой и неизвестной версии.
4. Добавить pure и PostgreSQL regression tests: понедельник, пауза, версия,
   correction, дедупликация и недельная квота.
5. Выполнить локальные проверки, независимый Quality Review, Architecture
   Review и выровнять только затронутую current-state Wiki после принятия.

## Критерии приёмки

- 28 сентября после A 25 сентября даёт B, а недельная квота начинается с нуля.
- После пропущенной недели A/B продолжается от последней достоверной
  классификации, без календарного сброса.
- Текущая классификация/исправление меняет новый read; связанная пара не
  считается дважды; несовместимая версия не даёт точную A/B.
- Garmin title и неклассифицированная силовая не создают A/B identity.
- Нет изменения активной программы, staging-данных или миграции.
- Тесты, независимая проверка и документационная валидация пройдены. Коммит,
  push и deploy вне scope.

## Результат

- Исправлен read `NextTrainingStep`: недельная квота считает текущую неделю,
  A/B продолжает последний достоверный якорь той же программы через понедельник
  и паузу.
- Проверены correction, связанная пара, совместимость версии, отсутствие
  вывода A/B из названия Garmin. Unit API: 301/301; целевые PostgreSQL
  integration: 14/14; lint, typecheck, build, docs validator пройдены.
- Независимый Quality Review принят. Staging-запись 21 сентября, активная
  программа и данные окружений не менялись.

## Architecture Review

1. Лишней сложности нет: исторический read нужен только для достоверного
   якоря; изменяемый cursor не введён.
2. Новых сервисов и deployable-границ нет.
3. Training владеет классификацией, связями и A/B; доменная граница сохранена.
4. ADR хранит решение, Wiki кратко описывает текущий контракт, план — ход
   выполнения; второй источник фактов не создан.
5. Решение остаётся масштабируемым без нового состояния: read возвращает два
   последних кандидата из каждого источника, corrections пересчитываются из
   current фактов. Упрощение до предыдущей недели нарушило бы паузу.
