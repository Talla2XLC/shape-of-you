# TASK-0089 — Немедленная запись завершённой тренировки

## Проблема

Coach понимает переданные пользователем упражнения и завершение тренировки, но
иногда спрашивает, нужно ли записать тренировку целиком. Это нарушает принятый
capture-first контракт TASK-0079: прямой отчёт уже является разрешением на
обычную идемпотентную запись.

## Причина

Общая MCP-инструкция запрещает повторное подтверждение, однако описания и
результаты Workout tools не содержат явной workout-specific формулировки
`immediately`, в отличие от Meal и Recovery. Поэтому модель допускает лишний
вопрос перед `record_workout_session`.

## Scope

1. Явно определить завершение тренировки и накопленный диалог как достаточный
   ввод для немедленной записи существующим typed Workout writer.
2. Запретить повторный вопрос «записать?» для обычной записи или коррекции.
3. После write требовать date-scoped typed read-back.
4. Ответ пользователю должен звучать как тренер: кратко подтвердить тренировку
   и дать одно полезное наблюдение без внутренних терминов.
5. При ошибке входного контракта выполнить одну безопасную повторную попытку,
   не показывая пользователю технические детали.
6. Добавить регрессионные MCP-тесты на инструкции, tool descriptions и результат
   записи.

## Ограничения

- Не менять доменную модель, схемы данных, migrations, OAuth scopes или API
  payloads.
- Не добавлять сервисы, базы данных, OAuth clients или chat UI.
- Commit, push и deployment остаются отдельными gates.

## Acceptance criteria

1. `record_workout_session` явно требует немедленной записи без duplicate
   confirmation после прямого отчёта или сигнала завершения.
2. `correct_workout_session` не просит подтверждать обычное уточнение повторно.
3. Write/read результаты направляют модель к естественному coach-ответу.
4. Ошибка аргументов допускает один бесшумный retry и не раскрывает mechanics.
5. Focused и full API tests, typecheck, lint, build и docs validation проходят.
6. Quality и Architecture Reviews дают `ACCEPT`.

## Результат

- Workout-specific MCP instructions теперь требуют немедленной записи прямого
  отчёта или завершённой тренировки из текущего сообщения и накопленного
  контекста без вопроса «записать?».
- `record_workout_session`, `correct_workout_session` и
  `list_workout_sessions` получили согласованный capture-first и natural-coach
  контракт.
- При ошибке входных аргументов агент получает одну безопасную бесшумную
  повторную попытку и не перекладывает исправление на пользователя.
- Focused MCP tests: 7/7; full API: 185/185; typecheck, lint, build, docs
  validation и diff check прошли.
- Quality Review и Architecture Review: `ACCEPT`.
