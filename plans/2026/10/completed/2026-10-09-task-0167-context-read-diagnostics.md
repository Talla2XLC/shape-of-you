# TASK-0167 — безопасная диагностика отказов чтения контекста

## Статус и разрешение

Оператор утвердил этот план сообщением «Го». Реализация выполнена в primary tree
и принята независимой Quality: `task-0167-quality-acceptance-20261009`.
Commit, push, deploy, миграции и изменения персональных фактов не входят в план.

## Проверенные факты

Повторный отказ `get_daily_decision_context` подтверждён безопасным событием
`mcp_context_read_failed`; последующее чтение прошло. Лог содержит только
`execution_failure`, без класса исключения и этапа отказа. Причина неизвестна.
Доступность отдельных Recovery facts не доказывает успех составного чтения.

## Архитектурная граница и альтернативы

Сохраняется MCP граница и решение из
[ADR дневного контекста](../../../../docs/adr/20260928-let-coach-decide-from-verified-daily-facts.md).
Это уточнение существующей диагностики TASK-0160, без нового публичного
контракта, доменной сущности, хранилища или алгоритма готовности.
Новый ADR не требуется при сохранении этих границ.

Рекомендуется закрытая классификация исключений и этапа отказа в существующем
логе. Сохранение текущего общего события снова оставит следующий отказ
необъяснимым. Запись исходного exception/stack раскрывает данные и не принимается.
Новые retries или ослабление проверки согласованности требуют доказанной причины
и отдельного решения; в этот план не входят.

## Объём реализации

1. Для двух существующих составных reads сохранить diagnostic UUID,
   `failureCategory=execution_failure` и прежний публичный error result.
2. Добавить фиксированный этап `execute` или `present`: исполнение service read
   отдельно от structured/text presentation и формирования MCP ответа.
3. Добавить закрытую категорию причины: `evidence_changed` для реального
   `DailyAssessmentEvidenceChangedError`, `database_failure` при распознанном
   SQLSTATE и `unclassified` во всех остальных случаях. Не принимать произвольное
   error.name за тип. Обход cause ограничить; определить однозначный приоритет
   классификации и проверить его тестами. Отсутствие SQLSTATE не исключает БД.
4. Сохранить запрет на input, Person, health values, SQL, parameters, credentials,
   exception message/stack и произвольные cause. Не менять диагностику writes.
5. Проверить оба reads: типизированную ошибку согласованности, распознанный
   SQLSTATE, неизвестную и поддельную ошибку, вложенные/циклические cause,
   ошибку presentation, приватность, последующий успех, отдельные auth/input пути.
6. Выполнить API typecheck/build/lint и релевантные тесты; провести независимую
   Quality. После принятия уточнить только affected Wiki описание диагностики,
   проверить документацию и соответствие действующим ADR.

## Критерии приёмки

- Синтетические сбои дают безопасную и однозначную причину/этап в логе.
- Внешний MCP error contract и поведение Coach сохраняются.
- Проверки согласованности, число повторов и факты пользователя не меняются.
- Privacy tests проверяют фактический лог и публичный ответ.
- Независимая Quality и `node scripts/validate-docs.mjs` проходят.
- Результат называется улучшением диагностики, а не исправлением неизвестной
  причины инцидента. Live delivery и проверка staging требуют отдельного разрешения.

## Результат

- Лог двух составных reads содержит `failureStage` и `failureReason`;
  типизированная ошибка согласованности имеет приоритет над вложенным SQLSTATE.
  Обход ограничен четырьмя узлами cause. Публичный error result сохранён.
- 407 unit tests и 11 MCP integration tests с изолированным PostgreSQL прошли.
  API typecheck/build/lint прошли. Независимая Quality проверила 32 read/write
  unit tests, typecheck, документацию и diff.
- Уточнена только affected Wiki страница Coaching. Новых сущностей, сервисов,
  данных, миграций, повторов или изменений проверки согласованности нет.
- Проверка архитектурной границы: существующий MCP adapter и тип доменной
  ошибки сохранены; дополнительных deployable boundaries и дублирования
  authority нет. Закрытые поля существующего лога — минимальный объём.
- Причина прошлого runtime-сбоя остаётся неизвестной. Commit, push и staging
  доставка не выполнены в рамках этой реализации.
