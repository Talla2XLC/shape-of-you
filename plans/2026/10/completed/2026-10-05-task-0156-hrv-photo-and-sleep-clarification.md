# TASK-0156 — фото HRV и уточнение сна после досыпа

## Статус и согласование

Оператор утвердил план сообщением «го». Реализация выполнена и принята независимой Quality.
Это уточнение маршрутизации существующих фактов и поведения Coach;
новые сущности, метрики, публичные schemas и миграции не предлагаются.

## Проверенный кейс

Coach смешал ночное значение HRV с семидневным средним и заявил, что
импорт не учёл досып, без проверенного чтения полной ночи. Дополнительно
он сообщил об отказе записи HRV; точный вызов и результат недоступны.
Персональные значения не включаются в документацию. Проверка использует
изолированные синтетические данные.

Контракт имеет hrv_rmssd, но не содержит отдельной семидневной метрики,
baseline range или Garmin HRV status. Уже существующая DailyContextNote
предназначена для значимого контекста без безопасного специализированного типа.
CurrentRecoveryContext возвращает отдельные факты со sourceChannel.

## Изменение

1. В MCP instructions и описании записи Recovery явно разделить ночной HRV,
   семидневное среднее, baseline и статус Garmin. Не подменять ночное значение
   семидневным средним.
2. Сохранять явно прочитанный ночной HRV существующим manual RecoveryObservation.
   Семидневное значение, baseline, статус и сообщение о досыпе сохранять
   существующей context note с исходным смыслом, когда typed Recovery metric
   этого не представляет. Не дублировать уже записанные сведения.
3. Отказ одного независимого факта не отменяет остальные. При блокировке
   безопасности не повторять ту же запись через другой инструмент в обход
   отказа; note применяется для отсутствующего семантического типа, а не
   как обход блокировки.
4. После сохранения прочитать owning-domain результат и свежий Daily Decision
   Context. Отличать показанные пользователем значения от account-импорта.
   Слова пользователя о досыпе не доказывают, что provider уже пересчитал сон;
   HRV сам по себе не устанавливает полную длительность сна.
5. Не переходить от «сегодня отдых» к «можно B» лишь из-за смены HRV или
   календарного поля. Объяснять рекомендацию по совокупности текущих фактов,
   самочувствию и нагрузке; конфликт источников сохранять видимым для Coach.

## Проверка

- Изолированный MCP/PostgreSQL сценарий: разные исходный account HRV и manual
  ночной HRV, note с отличающимся семидневным средним и baseline/status; сохранены происхождение,
  дата, идемпотентность и различие показателей, без подмены account-источника.
- Проверка неизвестной итоговой длительности после досыпа без выдуманного сна.
- Независимая Quality, проверка соответствия действующим ADR и canonical Wiki,
  docs validator и релевантные typecheck/lint/tests.
- Проверка реального Coach отдельно от локальных tests; наличие нужных
  инструментов и фактический ответ не объявлять доказанными заранее.

## Границы

Нет ручного provider sync/backfill, live writes, изменения алгоритма Recovery,
новых численных показателей или подмены семидневного среднего ночным.
Commit/push/deploy и записи реальных пользовательских фактов требуют
соответствующего отдельного разрешения.


## Результат и проверки

- MCP instructions, описания Recovery/context note и подсказка после отказа
  уточняют агрегацию HRV, происхождение фото, неизвестный полный сон и запрет
  обхода safety-блокировки.
- MCP/PostgreSQL сценарий подтверждает разные account/manual ночные значения,
  идемпотентность, отдельный подписанный контекст и неизменность импортированного
  сна. Adapter tests подтверждают доставку инструкции.
- Проверки: 6 integration и 11 adapter tests, API typecheck/build, targeted
  eslint, docs validator и diff check. Независимая Quality приняла изменения;
  Architecture Review не выявил новой архитектуры или лишних границ.
- Wiki обновлена в recovery-and-readiness. Текст note читается через
  list_daily_context_notes, а не из DailyDecisionContext; существующие ADR
  неполных фактов и субъективного самочувствия остаются authority.
- Поведение реального Coach и выполнение последовательности reread требуют
  отдельного разговора после доставки. Локальные tests этого не доказывают.
- Commit/push/deploy не выполнялись. Реальные пользовательские записи не менялись.
