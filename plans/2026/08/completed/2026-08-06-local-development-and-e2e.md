# TASK-0028 — Локальная среда API и Identity и одноразовый E2E-стек

## Цель

Сделать локальную разработку API и Identity воспроизводимой, не использовать
staging или внешние постоянные базы данных и запускать сквозную проверку одной
командой на чистых данных.

## Решение

- Для ручной разработки использовать Docker Compose с постоянными локальными
  volumes и отдельными PostgreSQL для API и Identity.
- Для запуска приложений на хосте хранить примеры окружения рядом с владельцем
  сервиса: `apps/api/.env.example` и `apps/identity/.env.example`.
- Сохранить существующие пакетные integration-тесты на Testcontainers.
- Для E2E создавать уникальный Compose project, использовать случайные внешние
  порты и всегда удалять его контейнеры и volumes после завершения.
- На первом этапе проверять обе цепочки миграций, liveness и database readiness.
- Не добавлять локальные edge, TLS, OAuth и браузерную автоматизацию passkey до
  появления соответствующего реализованного пользовательского сценария.

## Критерии завершения

- API и Identity используют разные БД, credentials, migrations и сети.
- `pnpm local:up` поднимает оба готовых сервиса на портах 3000 и 3001.
- `pnpm test:e2e` начинает с чистых project-scoped volumes и очищает их даже
  после ошибки.
- CI запускает ту же команду без специальных секретов.
- Локальный запуск не обращается к staging или операторской БД.
