# Перевод канонической документации на английский язык

## Цель

Сделать каноническую документацию однозначной и удобной для работающих с
проектом агентов: оставить планы на русском языке, а Wiki, ADR, README,
руководства, шаблоны и agent-facing тексты вести на английском.

## Утверждённое правило

- `plans/**/*.md` создаются и поддерживаются на русском языке.
- `docs/wiki/**/*.md`, `docs/adr/**/*.md`, README, руководства и шаблоны
  создаются и поддерживаются на английском языке.
- Все `AGENTS.md` остаются на английском языке.
- Общение с оператором ведётся на его языке, сейчас — на русском.
- Пути, IDs, frontmatter keys, команды, API names, enum values и другие
  стабильные контракты не переводятся.
- Локализованные строки приложения и реалистичные test fixtures не относятся
  к документации и сохраняют требуемый язык.

## Объём

### Входит

- Обновление language policy в `AGENTS.md` и документационном руководстве.
- Новый ADR о языке канонических документов.
- Перевод всех текущих страниц Wiki и ADR без изменения их смысла.
- Перевод корневого README, `docs/README.md`, `sources/README.md` и шаблонов.
- Перевод agent-facing сообщений валидатора документации и его fixtures там,
  где это не уменьшает проверочное покрытие.
- Проверка ссылок, frontmatter, ID, статусов и отсутствия случайной кириллицы в
  документационном scope вне `plans/`.

### Не входит

- Перевод планов.
- Изменение архитектурных решений, доменной модели или API contracts.
- Перевод пользовательских данных, локализованных ошибок или test fixtures
  приложения.
- Изменение production code, database, migrations или deployment.
- Commit и push без отдельного разрешения.

## Этапы

1. Зафиксировать новое языковое правило в workspace policy и ADR.
2. Перевести общие README и документационные шаблоны.
3. Перевести ADR, сохраняя status, links и decision semantics.
4. Перевести Wiki по разделам: start/product/vision/roadmap, architecture,
   domain, data, API и operations.
5. Проверить, что вне планов не осталось русскоязычных документов.
6. Запустить validator, docs tests и `git diff --check`.
7. Провести независимую проверку сохранности архитектурного смысла.
8. Перенести план в `completed` после принятия.

## Критерии приёмки

1. Workspace policy требует русский язык только для планов.
2. Все 80 канонических Wiki/ADR-файлов написаны на английском.
3. README, руководства и шаблоны документации написаны на английском.
4. Stable IDs, paths, frontmatter keys/values, commands и contracts сохранены.
5. Все относительные ссылки и обязательные разделы проходят validator.
6. Архитектурные решения, current-state claims и открытые ограничения не
   потеряны и не превращены в новые неподтверждённые факты.
7. Кириллица вне `plans/` остаётся только в явно локализованных application и
   test data, а не в документации.
8. Документационные tests и `git diff --check` проходят.

## Риски

- Массовый перевод может незаметно изменить смысл архитектурного ограничения;
  поэтому ADR, ownership, operations и source-of-truth pages проверяются
  отдельно.
- Механическое изменение technical identifiers может сломать ссылки или
  contracts; они сохраняются дословно.
- Текущие незакоммиченные изменения TASK-0022 принадлежат тому же рабочему
  дереву и не должны быть потеряны или перезаписаны.

## Результат

- Языковая политика обновлена: планы остаются на русском, каноническая и
  agent-facing документация ведётся на английском.
- Переведены 50 страниц Wiki и 30 существовавших ADR; добавлен новый ADR о
  языковой политике. Стабильные ID, frontmatter и технические контракты
  сохранены.
- Переведены README, документационные шаблоны и сообщения валидатора.
- Архитектурный аудит подтвердил сохранность ключевых ограничений и источников
  истины. Managed 4DreamTeam Wiki не изменялась.
- `node scripts/validate-docs.mjs`, `npm run test:docs`, `npm run lint` и
  `git diff --check` прошли успешно.
- Кириллица вне `plans/` осталась только в локализованных строках приложения и
  тестовых данных.
