# Сопоставлять единственную силовую пару за день без обязательного времени начала

## Context

Оператор отклонил этот путь: время существует у provider и должно сохраняться
из сообщения о начале тренировки. Сначала требуется исправить потерю или
несохранение temporal evidence, а не компенсировать это date-only matching.
Ни policy v4, ни новый persisted basis, ни CHECK migration не реализованы.
Оставшийся текст фиксирует отклонённое предложение, не текущую архитектуру.

Действующее правило требует точное начало подробной тренировки даже при
единственной подробной силовой и единственной совместимой Garmin-записи за
Person-local день. Обычный отчёт пользователя может честно содержать только
дату. Это превращает нормальную запись в повторный вопрос о совпадении.
Тесты проверяют отказ для date-only вместо полезного однозначного результата.

Оператор отверг обязательное время для очевидной пары. Снять ограничение
направления разрешено, но ниже конкретная политика ещё требует одобрения.
Правило прогрессии веса и TASK-0162 в этот объём не входят.

## Decision

1. Сохраняем explicit links, exact source identity и действующие подтверждённые
   title/time пути. Дополнительный путь применяется только к завершённой
   подробной силовой с честным `occurredAt = null`, выполненными силовыми sets
   и точной immutable program identity, если она задана.
2. На Person-local дату должна существовать ровно одна current завершённая
   подробная силовая и ровно одна current совместимая external силовая:
   Garmin-attributed, Intervals.icu, подтверждённый Person режим записи,
   без дистанции, длительностью не менее действующих 600 секунд.
   Для проверки количества учитываются все current факты даты, включая уже
   связанные, а не только свободные кандидаты или первые N записей истории.
3. Conflicting classification, explicit occupancy, несовместимая program
   identity или несколько кандидатов блокируют новый путь. Из generic Garmin
   title не выводится A/B: это берётся из подробной тренировки.
4. Если обе стороны имеют точное время, сохраняется действующая проверка
   разницы начал до 15 минут. Date-only путь не обходит известное противоречие
   во времени. В подробную сессию не подставляется время Garmin как якобы
   сообщённое пользователем; temporal precision сохраняется.
5. Association получает отдельный basis `confirmed_recording_day` и policy
   `automatic-activity-link-v4`. Это не новая доменная сущность или сервис.
   Additive API-owned migration расширяет существующий CHECK, сохраняя v2/v3
   и explicit rows. Новые значения укладываются в действующие varchar limits.
6. Late import, correction и замена/отзыв recording mode пересчитывают эти
   auto-links. Появление второго кандидата снимает недоказанную автоматическую
   связь и возвращает конкретный вопрос. Explicit link остаётся explicit.
   Общие Training consumers считают связанные факты одним занятием.

После принятия supersession прежнего recording-context ADR и affected Wiki
обновляются явно; proposed документ действующую политику не заменяет.

## Considered alternatives

- Требовать время при каждом отчёте: сохраняет прежнюю политику, но переносит
  техническое ограничение в пользовательский процесс. Оператор отверг вариант.
- Связывать любые ближайшие записи или любую силовую за дату: может привязать
  несколько занятий или чужую программу. Отклонено.
- Автоматически связывать только единственную совместимую пару при уже
  подтверждённом режиме записи: выбранный ограниченный компромисс. При двух
  кандидатах требуется уточнение, при одном не требуется обязательное время.

## Consequences

Обычный date-only отчёт связывается без повторного вопроса. Совпадение по дню
является явно принятой продуктовой эвристикой, а не доказательством identity
по timestamp. Запоздалый второй кандидат может отменить auto-link; это должно
быть проверено вместе с подсчётом нагрузки и последовательностью программы.
Доставка включает штатную миграцию только после отдельного deploy approval.

## Verification

- Unit: единственная date-only пара; разные даты; известное противоречивое время;
  in-progress и отсутствие силовых sets; неправильная program identity;
  неизвестный recording mode; два sessions/activities; explicit occupancy.
- PostgreSQL: current lineage, повторный sync без дубля, late second candidate,
  исправление/отзыв режима, preserved explicit links, единый подсчёт нагрузки.
- MCP flow: подробный date-only отчёт и imported activity дают следующую
  тренировочную опцию без вопроса о связи; неоднозначность даёт точный вопрос.
- Migration: clean/existing journals, v2/v3 rows, static 63-byte identifier gate.
- Независимая Quality, Architecture Review и canonical docs validation.
