# Разрешить предложение прибавки после одной тренировки с большим запасом

## Context

Оператор запросил изменить правило после вопроса о прессе: одна тренировка
может быть явно лёгкой, но действующий предикат всегда требует две последние
сопоставимые A/B. Это ограничение принятой политики, а не оценка физиологической
необходимости повторной тренировки. Свободное «легко» не заменяет фактические
weight, reps и RIR всех назначенных подходов.

## Decision

Правила полномочий и orchestration нового Coach заменены
[ADR базы знаний](20261009-let-coach-propose-working-weight-from-history.md).
Исторические snapshots, compatibility commands и технические гарантии хранения
сохраняют прежний смысл; supersession не переписывает существующие данные.

Оператор одобрил дополнение пункта 5 принятого ADR прогрессии узким
альтернативным предикатом 2026-10-07 вместе с implementation plan.

1. Обычный путь двух последних подходящих сессий сохраняется.
2. Одна последняя точная текущая сессия может дать `add_weight`, если все
   назначенные рабочие подходы имеют полный фактический external weight,
   reps и RIR, вес совпадает с назначением, повторения достигли верхней
   границы, а RIR каждого подхода не ниже `max(3, targetRir + 2)`.
   `targetRir` должен быть явно задан. Дополнительные подходы не заменяют
   неподходящие назначенные. Это предлагаемый продуктовый порог большого
   запаса, не медицинская норма и не обещание безопасности конкретной нагрузки.
3. Для нового пути в существующем reason enum добавить
   `single_session_high_reserve`. Evidence ссылается на реально использованную
   последнюю сессию; не выдавать предыдущую за подтверждение нового предиката.
4. Оба пути используют только явный `progressionIncrementKg`, не выше 10%
   текущего веса и 5 kg. Шаг не придумывается. Bodyweight, assisted, missing
   или conflicting facts, ambiguous assignments остаются вне прибавки.
5. Training projection, кандидаты и повторная проверка команды подтверждения
   используют один предикат. Сохраняются текущие Recovery gates, точная active
   version, явное принятие пользователем и атомарная смена одного назначения.
   Предложение не меняет программу и не разрешает будущую тренировку.
6. Нет новых таблиц, сервисов или сущностей. Принятое
   [дополнение audit](20261007-allow-single-session-working-weight-audit.md)
   требует одной additive migration nullable второй existing evidence ссылки.
   Scope — все подходящие
   назначения external_weight, включая пресс; специальных правил по имени
   упражнения нет. Исторические записи и текущая программа не переписываются.

## Considered alternatives

Остальные положения прежнего ADR сохраняются; меняется только обязательность
двух сессий для описанного исключения.

- Сохранить две тренировки без исключений: меньше изменений, но не выполняет
  запрос учитывать явно большой запас после одного выполнения.
- Повышать после одной сессии при любом допустимом RIR: проще, но одинаково
  трактует пограничный и явно лёгкий результат. Не рекомендуется.
- Узкое исключение с большим измеренным запасом: рекомендуемый вариант;
  требует полного RIR и сохраняет обычный путь при меньшем запасе.
- Пусть Coach сам трактует слово «легко»: не даёт проверяемого общего
  предиката и смешивает субъективную заметку с измеренными подходами.

## Consequences

Автоматическое предложение быстрее реагирует на явный запас, но основано на
одном самоотчёте и не подтверждает повторяемость. Порог одобрен оператором как продуктовая эвристика. Добавляется значение публичного reason enum; consumers
и MCP объяснения должны понимать новую причину. Текстовые заметки остаются
полезными фактами, но не дают автоматической прибавки без подходов.

## Verification

- Границы RIR: ровно порог, ниже порога хотя бы один подход, null targetRir,
  null фактический RIR, разный targetRir и запас по всем назначенным sets.
- Один подход не на верхней границе, неправильный вес, ambiguous assignment,
  extra sets, bodyweight/assisted и неизвестный шаг не обходят ограничения.
- Обычный путь двух сессий и пределы прибавки сохраняются.
- Projection/candidate/confirm согласованы; stale evidence, неподходящее
  текущее Recovery и гонка active version не принимают предложение.
- Contract enum, MCP explanation, independent Quality, Architecture Review,
  canonical Wiki alignment и docs validation до завершения.
